# План: price-ingest

Spec: `SPEC-price-ingest.md` (одобрен 2026-10-01). Задачите: `tasks/todo.md`.

## Преглед

Од работниот доказ (3 продавници, JSON на диск) до дневно преземање на сите 19 продавници во Велес од 4 синџири, со КАМ од PDF, следење на промените, предупредување за застарени ценовници и чување во Postgres. Секоја задача остава `npm test` зелен и `npm run fetch` функционален.

## Архитектонски одлуки

- **Ризикот прв.** КАМ PDF е непознат формат и единствената нова техничка работа без доказ. Затоа е задача 2, веднаш по безбедносната мрежа од тестови.
- **Тестови пред промени.** Постојните парсери (proverkanaceni, ramstore) немаат тестови. Задача 1 додава фикстури од вистинските извори пред да се менува `Offer` или регистарот.
- **Едно барање по сервер.** Преземањето се групира по сервер (host): различни сервери паралелно, иста серија последователно со пауза. Сега `fetch.ts` ги презема сите продавници паралелно, што со 13 продавници на Жито би било 13 истовремени барања кон ист сервер.
- **`PriceStore` интерфејс со два имплементации** (датотеки, Postgres) и **еден заеднички тест-пакет** за двете. Датотечната остава сè да работи локално без база.
- **Без ORM.** SQL миграции како обични `.sql` фајлови и мал извршувач. Драјвер: `@neondatabase/serverless` (работи и во Vercel функции и во Node скрипти, без pool). Нова зависност → потврда во задача 9.
- **Postgres на крај.** Сè до тогаш е тестирано на датотеки; базата е само уште една имплементација на истиот договор.
- **PDF библиотека:** `pdfjs-dist` (одобрено). Се користи само во `src/sources/kam.ts`.

## Граф на зависности

```
1 фикстури + Offer ─┬─ 2 КАМ PDF парсер ── 3 КАМ извор + продавници
                    └─ 4 регистар Велес + серија по сервер ── 5 npm run stores
                                                  │
                    6 промени ─┬─ 8 PriceStore + датотеки ── 10 Postgres PriceStore ── 11 fetch → Postgres
                    7 свежина ─┘                       9 Neon + миграции ─┘
```

6 и 7 се чисти функции и не зависат од 2–5 (може паралелно).

## Задачи (детали во `tasks/todo.md`)

### Фаза 1: КАМ (ризик прв)
1. Фикстури и тестови за постојните парсери; `Offer` добива `description`, `promoUntil`
2. КАМ PDF парсер со фикстура
3. КАМ извор: листа продавници → PDF → редови; 3 КАМ продавници во регистарот

**Checkpoint 1:** `npm run fetch -- kam` ги презема 3-те КАМ продавници (>1.500 производи секоја); тестови зелени; преглед со човек.

### Фаза 2: Сите продавници
4. Регистар на сите 19 продавници во Велес; преземање во серии по сервер; време по продавница
5. `npm run stores` — откривање продавници во Велес од изворите

**Checkpoint 2:** `npm run fetch` ги презема сите 19, ниедна над 300 сек; `npm run categories` без нови категории или со прегледани нови; преглед со човек.

### Фаза 3: Промени, свежина, чување
6. Промени меѓу две снимки (чиста функција)
7. Свежина: датум од маркетот → застарена продавница
8. `PriceStore` интерфејс, датотечна имплементација, заеднички тест-пакет; `fetch` пишува снимка + промени

**Checkpoint 3:** две последователни преземања создаваат промени; повторено преземање во ист ден не додава; застарените се печатат.

### Фаза 4: Postgres
9. Neon база (Vercel Marketplace) + миграции (табели `stores`, `offers_current`, `price_changes`)
10. Postgres имплементација на `PriceStore`, поминува заедничкиот тест-пакет; бришење промени постари од 1 година
11. `npm run fetch` пишува во Postgres кога е поставен `DATABASE_URL`

**Checkpoint 4 (модулот готов):** сите 8 критериуми од spec-от исполнети; `/review`; ажуриран spec ако нешто се сменило.

## Ризици

| Ризик | Влијание | Мерка |
|---|---|---|
| КАМ PDF редовите се кршат непредвидливо (имиња во 2–3 линии, акции со долг текст) | Високо | Читање по x-позиција на колоните од заглавјето; фикстура со повеќе страници; тест на бројот редови наспроти „Да/Не" |
| Жито org 55 / org 10 без производи | Ниско | Задача 4 ги проверува; продавница без храна останува во регистарот, означена |
| Изворите ја менуваат структурата | Средно | Парсерите фрлаат грешка кога табелата е празна; `npm run stores` и `npm run categories` откриваат промени |
| Оптоварување на изворите (13 продавници на Жито × до 49 страници) | Средно | Серии по сервер, пауза ≥1 сек, еднаш дневно; бројот барања се печати |
| Neon бесплатниот план (0,5 GB) | Ниско | Се чуваат само тековни цени и промени; бришење постари од 1 година |
| Поставување Neon бара ваша сметка на Vercel | Средно | Задача 9 е последна; дотогаш сè работи на датотеки |
