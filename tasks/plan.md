# План: item-options

Spec: `SPEC-item-options.md` (одобрен 2026-10-02). Задачите: `tasks/todo.md`. Претходни модули: `tasks/price-ingest/`, `tasks/product-matching/`, `tasks/price-history/`, `tasks/web-app/` (таму останува отворен Checkpoint C — `/review` на web-app; се прави заедно со прегледот на овој модул).

Претпоставки за отвореното во spec-от (може да се сменат на Checkpoint A): продавница со замени се рангира по сума како досега, со значка „N замени"; свинско месо = бут, плешка, кременадли/каре, вешалица, ребра (+ мелено).

## Архитектонски одлуки

- **Брендот е податок, не правило.** `data/brands.json` (рачно прегледан, како мапите): бренд → име, шаблони, типови, алијаси во списокот. Брендот на кандидатот се пресметува при `build-data` и оди во пакетот како `b`; телефонот не носи шаблони.
- **Ставката носи ниво.** `BasketLine` добива опционално `option: { level: "any" | "brand" | "exact"; brand?; size? }`. Една чиста функција (`pickFor(line, candidates)`) го прави ограничувањето и замената (exact → brand → any) и враќа купување со `match` и `reason`. `compareBasketWith` ја користи; без опција — исто како денес (постојните тестови непроменети).
- **Брендот на кандидатот** е поле на `Candidate` (`brand?: string`), пополнето од изворот: `findCandidates` (командите, со `data/brands.json`) или пакетот (`b`).
- **Свинско месо по делови** е промена во каталогот и мапите (нови типови), не во логиката; „свинско месо" станува „прашај" во списокот.
- **Без нови зависности.**

## Граф на зависности

```
1 brands.json + brandOf + npm run brands ── 2 пополнување на брендовите
            └── 3 ниво на ставката (pickFor, замена) ── 4 брендови во списокот („нескафе", „персил")
5 свинско месо по делови (независно)
3, 4, 5 ── 6 апликацијата (Колку точно?, значки, Пребарај) ── 7 објава
```

## Задачи

### Фаза 1: Логика и податоци
1. `data/brands.json`, `brandOf(offer, typeId)`, бренд во кандидатите и пакетот, структурни тестови, `npm run brands`
2. Пополнување на брендовите за ≥ 15 типа (рачен преглед со `npm run brands`)
3. Ниво на ставката: `pickFor` (exact → brand → any, причина), `compareBasketWith` со опции
4. Брендови во списокот: „нескафе" → инстант кафе + Nescafé, „персил" → прашок + Персил; „нескафе" излегува од алијасите на инстант кафе
5. Свинско месо по делови: нови типови, мапи (категории + КАМ), „свинско месо" бара избор

**Checkpoint A:** критериуми 1–6 и 8 (тестови, вистински пакет); преглед со човек (вкл. двете претпоставки).

### Фаза 2: Апликација
6. Кошничка: „Колку точно?" во панелот на ставката, значка „замена" и причина во деталите; Пребарај: „Додај токму овој производ" / „Додај го брендот"; избор на дел за свинско месо
7. Проверка на телефон, објава на kusur.online

**Checkpoint B:** критериум 7; `/review` (item-options + отворениот web-app); spec-ови; Second Brain.

## Ризици

| Ризик | Влијание | Мерка |
|---|---|---|
| Бренд во описот кај КАМ, латиница/кирилица, скратувања („ПЕРС.") | Средно | Шаблоните врз име + опис, со изедначување на латиница (`normalizeLookalikes`); `npm run brands` ги покажува непрепознаените |
| Еден бренд за повеќе типови (Персил: прашок, гел, капсули) | Ниско | Брендот важи по тип во `brands.json`; ставката е секогаш тип + бренд |
| „Ист производ" ретко има пар (различни пакувања по синџир) | Средно (очекувано) | Замената по ред exact → brand → any, секогаш видлива |
| Делови на свинско немаат исти зборови по синџир | Средно | `require` по дел од вистинските имиња; покриеност проверена со `npm run categories` |
| Пакетот расте со бренд | Ниско | `b` само кога е препознаен; граница 2 MB се проверува во `build-data` |
