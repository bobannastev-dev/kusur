# План: price-ingest

Spec: `SPEC-price-ingest.md` (одобрен 2026-10-01). Задачите: `tasks/todo.md`.

## Преглед

Од работниот доказ (3 продавници, JSON на диск) до преземање на сите 19 продавници во Велес од 4 синџири, со КАМ од PDF, следење на промените и предупредување за застарени ценовници. **Сè работи локално, со датотеки.** Базата (Postgres кај давател што ќе се одбере подоцна) е посебна фаза, надвор од ова градење. Секоја задача остава `npm test` зелен и `npm run fetch` функционален.

## Архитектонски одлуки

- **Ризикот прв.** КАМ PDF е непознат формат и единствената нова техничка работа без доказ. Затоа е задача 2, веднаш по безбедносната мрежа од тестови.
- **Тестови пред промени.** Постојните парсери (proverkanaceni, ramstore) немаат тестови. Задача 1 додава фикстури од вистинските извори пред да се менува `Offer` или регистарот.
- **Едно барање по сервер.** Преземањето се групира по сервер (host): различни сервери паралелно, иста серија последователно со пауза. Сега `fetch.ts` ги презема сите продавници паралелно, што со 13 продавници на Жито би било 13 истовремени барања кон ист сервер.
- **`PriceStore` интерфејс со два имплементации** (датотеки, Postgres) и **еден заеднички тест-пакет** за двете. Датотечната остава сè да работи локално без база.
- **Локално прво.** Чувањето е во датотеки преку интерфејсот `PriceStore`. Базата подоцна е само уште една имплементација на истиот договор и го поминува истиот тест-пакет, без промени во остатокот од кодот. Давателот (Neon, Supabase или друг) не е одбран; двата се Postgres, па истиот SQL важи.
- **PDF библиотека:** `pdfjs-dist` (одобрено). Се користи само во `src/sources/kam.ts`.

## Граф на зависности

```
1 фикстури + Offer ─┬─ 2 КАМ PDF парсер ── 3 КАМ извор + продавници
                    └─ 4 регистар Велес + серија по сервер ── 5 npm run stores
                                                  │
                    6 промени ─┬─ 8 PriceStore + датотеки ┄┄ (подоцна: Postgres)
                    7 свежина ─┘
```

6 и 7 се чисти функции и не зависат од 2–5 (може паралелно).

## Задачи (детали во `tasks/todo.md`)

### Фаза 1: КАМ (ризик прв)
1. Фикстури и тестови за постојните парсери; `Offer` добива `description`, `promoUntil`
2. КАМ PDF парсер со фикстура
3. КАМ извор: листа продавници → PDF → редови; 3 КАМ продавници во регистарот

**Checkpoint 1:** `npm run fetch -- kam` ги презема 3-те КАМ продавници (>1.500 производи секоја); тестови зелени; преглед со човек.

### Фаза 2: Сите продавници
4. Регистар на сите 19 продавници во Велес; преземање во серии по сервер; време по продавница
5. `npm run stores` — откривање продавници во Велес од изворите

**Checkpoint 2:** `npm run fetch` ги презема сите 19, ниедна над 300 сек; `npm run categories` без нови категории или со прегледани нови; преглед со човек.

### Фаза 3: Промени, свежина, чување
6. Промени меѓу две снимки (чиста функција)
7. Свежина: датум од маркетот → застарена продавница
8. `PriceStore` интерфејс, датотечна имплементација, заеднички тест-пакет; `fetch` пишува снимка + промени

**Checkpoint 3 (модулот готов, локално):** две последователни преземања создаваат промени; повторено преземање во ист ден не додава; застарените се печатат; критериумите од spec-от исполнети; `/review`.

### Подоцна (не е дел од ова градење): Postgres
Кога ќе се одбере давател: миграции (табели `stores`, `offers_current`, `price_changes`), Postgres имплементација на `PriceStore` што го поминува истиот тест-пакет, бришење промени постари од 1 година, `fetch` пишува во базата кога е поставен `DATABASE_URL`. Ќе се испланира тогаш, како посебни задачи.

## Забележано за подоцна (надвор од price-ingest)

- **Рамстор „ЛОЈАЛНОСТ“:** дел од акциите (тип на акција „ЛОЈАЛНОСТ“, колона „ПОЕНИ“) важат само со клуб-картичка. Продажната цена во ценовникот е таа цена. За `basket`: да се означи или да се користи редовната цена за купувач без картичка. (Задача 1, 2026-10-01)

- **КАМ податоци (задача 2):** цел PDF на КАМ Велес (Id 40) → 1.708 производи за 3 сек. Некои единечни цени на КАМ се погрешни во изворот („1 гр = 173.33 ден." за јогурт од 900 г; „1 мл = 1127.14 ден." за џин од 700 мл), а некои имиња се пресечени во изворот („…НЕРАФИНИРАНО31"). Парсерот ги чува како што се; `product-matching` треба да претпочита количина од името пред единечната цена (веќе е така).

- **КАМ без категории (задача 3):** `npm run categories` го покажува КАМ како нова категория `""` со сите производи — очекувано до `product-matching`. Во `basket`, продавница без ниту еден поврзан производ се печати како „—" наместо со име (план без користени продавници).
