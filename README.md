# Каде поевтино?

Споредба на **цела кошничка** низ маркетите во Македонија: внесуваш список, добиваш каде е најевтин целиот список и дали вреди да одиш во втора продавница.

Состојба: работен доказ (командна линија) за Велес со три продавници — Жито Трговски, Стокомак Велес и Рамстор Велес.

## Употреба

Потребен е Node.js 22.18 или понов (TypeScript се извршува директно, без build).

```
npm install
npm run fetch                                   # ги презема денешните ценовници (~4 мин)
npm run basket -- "млеко, 10 јајца, сирење, кафе и прашок за перење"
npm run basket -- --max-stores 1 "леб, 2 млека, јогурт"
npm test
```

## Од каде се цените

Од 18 април 2025 големите синџири се законски обврзани секој ден до 10 часот да ги објават продажните цени на своите веб-страници (измени на Законот за заштита на потрошувачите, Службен весник од 4 март 2025). Ги читаме тие јавни ценовници, по продавница:

| Синџир | Извор | Преземање |
|---|---|---|
| Жито | `zito.proverkanaceni.mk/?org=<продавница>` | табела по страници, 100 реда |
| Стокомак | `stokomak.proverkanaceni.mk/?org=<продавница>` | иста платформа |
| Рамстор | `ramstore.com.mk/marketi/<продавница>/` | цела табела во едно барање |

Преземањето е со искрен User-Agent и пауза меѓу барањата. Снимките се чуваат во `data/snapshots/<датум>/<продавница>.json`.

Сè уште не се вклучени: Тинекс (`ceni.tinex.mk`), КАМ (`kam.com.mk/ceni-vo-marketi.nspx`, се вчитува со JavaScript) и Кипер (табела преку AJAX). Веро нема продавница во Велес.

## Како работи

1. `src/list.ts` го чита списокот („кило сирење, 2 литри млеко, 10 јајца") и го претвора во типови производи со количина.
2. `src/catalog.ts` има 171 тип производ: што е „млеко", „сирење", „прашок за перење"…, во која единица се мери и колку се купува ако не е кажано.
3. `data/category-map.json` кажува во кој тип спаѓа секоја категорија на секој синџир (1.430 категории, 542 мапирани). Секој синџир има своја номенклатура: Рамстор „ТРАЈНО МЛЕКО", Стокомак „МЛЕКА ТРАЈНИ", Жито „Млеко ухт". Празна листа `[]` значи дека категоријата свесно не е дел од кошничка (облека, играчки, техника…).
4. Кога една категорија меша повеќе типови (Стокомак „СИРЕЊЕ вакуум" има кравјо, овчо, биено), одлучува името на производот преку правилата `require` / `exclude` во каталогот.
5. `src/match.ts` за секој тип ги наоѓа соодветните редови, ја одредува количината на пакувањето (од името, па од објавената единечна цена) и пресметува колку чини потребната количина. Не се купуваат повеќе од 6 пакувања по ставка.
6. `src/basket.ts` ја собира кошничката по продавница и го бара најдобриот план со најмногу N продавници.

## Одржување на мапата

```
npm run categories
```

Покажува нови категории што ги нема во мапата (маркетите додаваат и преименуваат), колку производи паѓаат во секој тип по синџир, и мапирања од кои ниеден производ не поминал низ правилата. Нова категорија се додава во `data/category-map.json` со соодветните типови или со `[]`. Тестовите (`npm test`) проверуваат дека секој тип во мапата постои, дека `exclude` не исклучува цела категорија и дека во мешана категорија најмногу еден тип нема правило по име.

Мапата е првиот дел за кој е наменето AI: модел ги предлага типовите за нови категории, човек ги прегледува, а резултатот е обичен фајл во проектот.

## Познати ограничувања

- „Најевтино" значи најевтиниот производ од типот во таа продавница, па брендовите меѓу продавниците се разликуваат (пр. сирење со 25% м.м. наспроти полномасно).
- Маркетите пишуваат количини и единечни цени неконзистентно; производ без препознатлива количина се прескокнува.
- Жито Трговски (Велес) нема свеж зеленчук и овошје во ценовникот.
- По една продавница од синџир. Цените меѓу продавници од ист синџир може да се разликуваат.
