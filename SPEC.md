# Spec: Каде поевтино?

Статус: мапата на модули и заедничките правила се одобрени (2026-10-01). Секој модул има свој spec (`SPEC-<модул>.md`), кој се пишува и одобрува пред да се гради модулот.

## Цел

Веб-апликација за телефон што ти кажува каде во Велес е најевтина **целата кошничка**, не поединечен производ. Купувачот внесува список („млеко, 10 јајца, кило сирење, прашок за перење"), а апликацијата покажува:

- колку чини целиот список во секоја продавница;
- дали вреди да се оди во две продавници и колку се заштедува;
- кои од производите што ги следи поевтиниле од последното отворање;
- можност да пријави погрешна цена или погрешно спарен производ.

**Корисник:** жител на Велес што купува во синџирски маркети и сака да заштеди без да споредува рачно. Нема сметки, нема регистрација.

**Извор на цени:** законски објавените дневни ценовници на синџирите (Закон за заштита на потрошувачите, обврска од 18.04.2025). Секоја цена се прикажува со датумот на ажурирање од маркетот.

**Опфат на првата верзија:** Велес, синџирите Жито, Стокомак, Рамстор и КАМ. Без AI: списокот се внесува со предлози додека се пишува и со речник на зборови.

## Мапа на модули

| Модул | Одговорност | Зависи од | Spec |
|---|---|---|---|
| `price-ingest` | Дневно преземање на ценовниците на сите продавници од 4-те синџири во Велес и чување на тековните цени и промените | — | `SPEC-price-ingest.md` |
| `product-matching` | Каталог на типови производи, мапа категорија → тип, правила по име, рачно прегледана мапа производ → тип за КАМ | `price-ingest` | `SPEC-product-matching.md` |
| `basket` | Список → типови и количини; цена на кошничката по продавница; најдобар план со најмногу 2 продавници | `product-matching` | `SPEC-basket.md` |
| `price-history` | Историја од промените; „следени производи" (во прелистувачот) и приказ на поевтинетите при отворање | `price-ingest`, `product-matching` | `SPEC-price-history.md` |
| `price-reports` | Анонимна пријава на погрешна цена/спарување; листа за преглед | `product-matching` | `SPEC-price-reports.md` |
| `web-app` | Next.js апликација за телефон што ги поврзува модулите | `basket`, `price-history`, `price-reports` | `SPEC-web-app.md` |

Ред на градење: `price-ingest` → `product-matching` → `basket`, `price-history`, `price-reports` → `web-app`

Модулите `price-ingest`, `product-matching` и `basket` постојат како работен доказ (командна линија, 3 синџири, по една продавница). Нивните spec-ови го опишуваат тоа што е направено и тоа што недостига.

## Технологија

- **Јазик:** TypeScript, ESM, Node.js 22.18+ (ги извршува `.ts` директно).
- **Логика** (`price-ingest`, `product-matching`, `basket`, `price-history`): чист TypeScript во `src/`, без зависност од Next.js, за да се тестира и извршува и од командна линија.
- **Веб:** Next.js 16 (App Router) на Vercel. Се додава во модулот `web-app`.
- **Чување:** засега локално, во датотеки (`data/`). Подоцна Postgres кај давател што ќе се одбере (Neon, Supabase или друг). Логиката зависи само од интерфејсот `PriceStore`, не од давателот. Се чуваат тековните цени и само промените, не целосни дневни снимки (19 продавници × ~4.000 производи дневно би било премногу за бесплатен план).
- **Распоред:** засега рачно (`npm run fetch`); автоматски дневно кога ќе се одбере каде ќе работи (Vercel Cron или друго).
- **Лично:** списоците и следените производи се во прелистувачот (localStorage). Серверот не чува лични податоци.

## Команди

```
npm install                     # зависности
npm test                        # сите тестови (node:test)
npm run typecheck               # проверка на типови (tsc, без компајлирање)
npm run fetch                   # презема ценовници (npm run fetch -- zito за еден синџир)
```

Секој модул ги додава своите команди во својот spec (на пр. `npm run dev` во `web-app`).

## Стил на код

Коментарите и пораките кон корисникот се на македонски; имињата во кодот се на англиски. Мали функции со една задача, без класи каде што е доволна функција, без зависности ако вградениот Node.js е доволен.

```ts
/** Најевтиниот начин да се купи `need` од дадениот тип во една продавница. */
export function cheapestPurchase(store: SnapshotFile, type: ProductType, need: number): Purchase | null {
  let best: Purchase | null = null;
  for (const candidate of findCandidates(store, type)) {
    const p = purchase(candidate, need);
    if (p.packs > MAX_PACKS) continue;
    if (!best || p.cost < best.cost) best = p;
  }
  return best;
}
```

- Типови од TypeScript без `any`; податоците од надвор (HTML, PDF, база) се проверуваат на границата.
- Регекси за кирилица со `u` и `(?!\p{L})` наместо `\b`.
- Без форматер засега; 2 празни места, двојни наводници, `;` на крај.
- Само синтакса што Node може да ја избрише (`erasableSyntaxOnly`): без `enum`, `namespace`, параметри-својства; `import type` за типови.

## Тестирање

- `node:test` + `node:assert/strict`, фајлови `*.test.ts` до кодот.
- Парсерите се тестираат со вистински примери од ценовниците (имиња, единечни цени, HTML/PDF исечоци) — не со измислени формати.
- Логиката на кошничката се тестира со мали рачно направени продавници и мапа.
- Мапата на категории има структурни тестови (секој тип постои, `exclude` не исклучува цела категорија, итн.).
- Мрежата не се допира во `npm test`. Вистинските ценовници се проверуваат со `npm run fetch` и `npm run categories`.
- Секоја поправена грешка од вистински податоци добива тест со тој пример.

## Граници

**Секогаш:**
- `npm test` и `npm run typecheck` да поминуваат пред секој commit.
- Искрен User-Agent со контакт и пауза меѓу барањата кон ист сервер.
- Секоја прикажана цена со датумот на ажурирање од маркетот.
- Spec-от се ажурира пред да се смени однесување што го опишува.

**Прво прашај:**
- Нова зависност (npm пакет) или надворешен сервис (база, е-пошта, AI).
- Нов синџир или град надвор од Велес.
- Шема на базата и миграции.
- Deploy на Vercel, нов домен, cron распоред.
- Чување на какви било податоци за корисниците на сервер.

**Никогаш:**
- Тајни (клучеви, connection strings) во git или во Second Brain.
- Преземање што ги заобиколува ограничувањата на сајтовите или ги оптоварува (паралелни барања кон ист сервер, без пауза).
- Прикажување цена без извор и датум, или измислена/проценета цена како вистинска.
- Бришење или ослабување тест за да помине промена.
- Лични податоци (е-пошта, локација) без посебна одлука.

## Отворено

- AI (Mistral) за читање слободен список и за предлог-мапирање на КАМ: следна фаза по првата верзија.
