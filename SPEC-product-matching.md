# Spec: product-matching

Модул од `SPEC.md`. Зависи од: `price-ingest`. Од него зависат: `basket`, `price-history`, `price-reports`.

## Цел

Секој ред од ценовниците на сите 4 синџири да може да се поврзе со **тип производ** („Млеко (кравјо, трајно)", „Бело сирење (кравјо)"…), за кошничката да се споредува фер низ сите продавници, вклучително и КАМ.

Што постои (работен доказ): каталог од 171 тип (`src/catalog.ts`), рачно прегледана мапа категорија → тип за Жито, Стокомак и Рамстор (`data/category-map.json`, 1.430 категории), правила по име (`require` / `exclude`), количина на пакување (`src/match.ts`, `src/parse.ts`), преглед `npm run categories`.

Што се додава:

1. **Нови категории на Жито** — 148 категории од поголемите продавници (Центар, Ване, Општина), сè уште непрегледани.
2. **КАМ** — нема категории; поврзување по име и опис преку правила што **предлагаат** тип, и рачно прегледана мапа производ → тип.
3. **Клуб-цени на Рамстор** — акциите „ЛОЈАЛНОСТ" важат само со клуб-картичка; во споредбата се користи редовната цена, а клуб-цената се прикажува како забелешка.
4. **Познати грешки при читање количина** — тоалетна хартија „16рол 3/1".

Одлуки (2026-10-02): КАМ со правила + рачен преглед; цена без картичка, клуб-цената означена; „најевтино од типот + покажи го" (без нивоа на квалитет — ако треба потесно, нов тип); каталогот останува 171 тип, плус типови што јасно недостигаат при прегледот.

## Факти од изворите (2026-10-02)

- **КАМ:** 2.139 уникатни имиња низ трите продавници во Велес, 2.011 уникатни описи; навистина нови производи ~6 дневно (дневните „нови/исчезнати" по продавница се главно асортиман). Описот е бренд + вид производ: „COCA COLA ПИЈАЛАК ГАЗИРАН", „THOMY МАЈОНЕЗ", „FIESTA КАКАО ВО ПРАВ". Името е скратено, често со количина: „ЧОКОЛ.МЛЕЧНО АЛПИКО 100ГР".
- **Рамстор, колона „ТИП НА АКЦИЈА" (индекс 8):** „АКЦИСКА ПРОДАЖБА" (598), „ЛОЈАЛНОСТ" (278), „ПОНУДА" (92). Кај „ЛОЈАЛНОСТ" продажната цена е со картичка, а редовната (колона 5) е без: „БЕНЛИАН РАЈС КЕЈК… 100 ГР" → 45 со картичка, 55 без.
- **Жито/Стокомак, колона „Вид на продажно поттикнување" (индекс 7):** „промотивна цена", „акциска цена" — без клуб-цени.
- **Жито:** 148 нови категории (на пр. „Чаеви", „Пуканки", „Месо свинско", „Детска паста за заби", „Растителна паштета", „Пушено месо од живина").

## Однесување

### Вид на акција во ценовникот
- `Offer` добива `promoKind` (текстот од колоната за вид на акција, без толкување; `null` ако нема). Промена во парсерите на `price-ingest` (Проверка на цени: индекс 7, Рамстор: 8, КАМ: колона „Вид").
- Функција `comparisonPrice(offer)`: ако `promoKind` е клуб-цена (Рамстор „ЛОЈАЛНОСТ") и има редовна цена → редовната цена; инаку продажната. Споредбата на кошничката ја користи неа.
- Резултатот за ставката го носи и клуб-цената (`loyaltyPrice`), за приказ: „55 ден. (со клуб-картичка 45)".

### Мапа категорија → тип (Жито, Стокомак, Рамстор)
- Сите категории што ги покажува `npm run categories` се прегледуваат: тип(ови) или `[]`. Истите правила и тестови како досега.
- Нов тип во каталогот само ако при прегледот јасно недостига (храна/хигиена што луѓето ја пишуваат во список).

### Мапа производ → тип (КАМ)
- Нов фајл `data/product-map.json`: `{ "<синџир>": { "<име на производ>": ["тип", …] | [] } }`. Важи за синџири без категории (засега само КАМ). Ист формат на преглед како мапата на категории: еден ред по производ, `[]` = свесно не е дел од кошничка, без клуч = нов производ за преглед.
- **Предлози:** `npm run propose` за секој непрегледан производ на КАМ предлага тип(ови) по правила врз името и описот, и ги запишува во `data/review/КАМ-proposals.json` (не директно во мапата). Правилата се клучни зборови по тип во `src/keywords.ts` (не во секој ред на каталогот), закотвени на почетокот на описот по марката („BELLA FARM МЛЕКО ТРАЈНО" → „МЛЕКО ТРАЈНО"); тип без клучен збор го користи својот `require`. Потоа важат `require` / `exclude`. Првиот збор во описот може да означи непрехрана (облека, цигари, садови…).
- **Преглед:** човек (засега јас, во сесија) ги потврдува или поправа предлозите и тие влегуваат во `data/product-map.json`. Предлог никогаш не влегува во споредбата без преглед.
- **Нови производи:** `npm run categories` го покажува бројот и листата на непрегледани производи на КАМ. Додека не се прегледаат, не учествуваат во споредбата.
- `matchesType` за синџир без категории ја користи мапата производ → тип наместо мапата на категории; `require` / `exclude` се проверуваат врз **името и описот** (името на КАМ е скратено: „ЧОКОЛ.МЛЕЧНО АЛПИКО"). `npm run categories` ги покажува и мапираните производи што правилата ги одбиваат.

### Количини
- „16рол 3/1" (тоалетна хартија: 3 пакувања по 16 ролни) → 48 парчиња; „8+2/1" и „8/1+2" → 10 (само без празни места: „ПЕЛЕНИ 15+ 40/1" = 40); „8+2" и „10/1" како досега.

## Критериуми за успех

1. `npm run categories` покажува **0 нови категории** за Жито, Стокомак и Рамстор (сите 148 прегледани).
2. `data/product-map.json` има запис за **секое** име на КАМ од најновите снимки на трите продавници; `npm run categories` покажува 0 непрегледани производи на КАМ.
3. За основните типови (млеко, јајца, бело сирење, кашкавал, леб, шеќер, брашно, масло, ориз, кафе, јогурт, путер, прашок за перење, тоалетна хартија, паста за заби) КАМ има барем еден производ во секоја од трите продавници, или е запишано дека КАМ Велес го нема тој тип.
4. Примерната кошничка „млеко, 10 јајца, сирење, кафе и прашок за перење" има цена во сите 9 продавници (вклучително трите КАМ), или е јасно која ставка недостига.
5. Тест: ред на Рамстор со „ЛОЈАЛНОСТ" (45 / редовна 55) во споредбата се смета 55, а резултатот ја носи клуб-цената 45. Ред „АКЦИСКА ПРОДАЖБА" се смета со продажната цена.
6. Тестови: секој тип во `product-map.json` постои во каталогот; предлозите за неколку вистински имиња/описи на КАМ (фикстура) се точни („COCA COLA ПИЈАЛАК ГАЗИРАН" → газиран сок; „ALPIKO ЧОКОЛАДО МЛЕЧНО" → чоколадо, не млеко).
7. Тест: „ТОАЛЕТ ПЕРФЕКС СОФТ ЛАЈТ 16рол 3сл 3/1" → 48 парчиња.
8. `npm test` и `npm run typecheck` поминуваат.

## Тестирање

- Правилата за предлози и `comparisonPrice` — чисти функции, вистински примери од ценовниците.
- Мапите — структурни тестови како постојните (типовите постојат; `exclude` не исклучува цела категорија).
- Вистинските снимки: `npm run categories` (покриеност по тип и синџир, непрегледани).

## Граници (додатно на `SPEC.md`)

- **Секогаш:** предлог на тип за КАМ влегува во мапата само по преглед.
- **Прво прашај:** нов тип во каталогот што не е очигледен од прегледот; промена на значењето на постоен тип.
- **Никогаш:** клуб-цена како редовна цена во споредбата без ознака.

## Резултат (2026-10-02)

Сите 8 критериуми исполнети: 152 нови категории прегледани (33 мапирани); 2.122 производи на КАМ прегледани (995 со тип); сите 15 основни типови во сите три продавници на КАМ; примерната кошничка има цена во сите 9 продавници (Жито Ване 552 … КАМ 8-ми Септември 844 ден.).

## Отворено

- Дали прегледот на предлозите за КАМ подоцна да го прави AI (Mistral) со човечка потврда — после првата верзија.
- Снимката на Рамстор од 2026-10-01 нема `promoKind`: во историја (`price-history`) клуб-цените од тој ден би изгледале како обични — да се означи или да се прескокне.
- Пренесена „тековна листа" за производите што случајно недостигаат кај Жито (од прегледот на `price-ingest`) — припаѓа на `price-history`.
