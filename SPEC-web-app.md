# Spec: web-app

Модул од `SPEC.md`. Зависи од: `basket`, `price-history` (и `product-matching`, `price-ingest` преку нив). Последен модул пред прва јавна верзија.

## Цел

Апликација за телефон (веб, може да се „инсталира" на почетниот екран) со четири екрани во мени долу: **Кошничка**, **Поевтинето**, **Пребарај**, **Продавници**. Изгледот е одобрената макета (https://claude.ai/artifact/AQCJhGzxbfJwoaqrHReiYi): топол преливник килибар → виолетово, стаклени картички, меури за производите во кошничката, голема бројка за вкупната цена, лебдечко стаклено мени; светла и темна тема по телефонот; Unbounded (наслови) + Onest (текст), и двата со кирилица.

Цените секој ден автоматски: GitHub Actions ги презема наутро и објавува нова верзија на Vercel. Без сметки, без сервер со лични податоци: кошничката, следените типови и последната посета се во прелистувачот (`localStorage`).

Одлуки (2026-10-02): GitHub Actions + Vercel; четирите екрани; светла + темна; макетата одобрена.

## Архитектура

```
GitHub Actions (секој ден 08:30 UTC = 10:30 во Велес)
  1. ги враќа податоците од претходниот ден (data/: снимки 7 дена + промени 365 дена)
  2. npm run fetch            → нови снимки и промени, бришење по рок
  3. ги зачувува податоците   (за следниот ден)
  4. npm run build-data       → public/data/*.json (мал пакет за телефонот)
  5. next build (static export) → објава на Vercel
Телефон
  ги вчитува public/data/*.json и сè пресметува локално
  (compareBasket, dropsSince, promoCheck — истите функции од src/)
```

- **Статичка апликација** (Next.js 16, App Router, `output: "export"`): нема серверски функции, нема база. Vercel служи датотеки.
- **Пакет за телефонот** (`npm run build-data`, нов `src/publish/`):
  - `types.json`: за секој тип производ и секоја продавница — кандидатите од `findCandidates` (име, цена, редовна цена, вид на акција, количина на пакување, на мерење) и **серијата на цени** за секој кандидат (од `allSeries`), за `dropsSince` и `promoCheck` на телефонот. Цел: ≤ 2 MB необработено.
  - `stores.json`: продавници, број на производи, кога се ажурирани, дали е застарено.
  - `catalog.json`: типовите (име, алијаси, единица, стандардна количина) — за меурите и читањето на список.
  - Пакетот носи верзија и датум; телефонот го чува последниот во кешот на прелистувачот.
- **Пресметките на телефонот** се истите TypeScript функции (`compareBasket`, `cheapestPurchase`, `dropsSince`, `promoCheck`, `parseList`), без `node:fs`: модулите што читаат датотеки (мапите, складиштето) остануваат само за `build-data`. Кандидатите се веќе пресметани, па телефонот не ги вчитува мапите.
- **Чување на податоците меѓу деновите** (во Actions): архива `data.tar.zst` како прилог на GitHub Release (`data-latest`), плус дневни копии за последните 7 дена (за враќање ако нешто се расипе). Без база и без нов давател.

## Екрани и однесување

### Кошничка (почетен екран)
- Меури за ставките (тип + количина); допир → помал панел: количина (−/+), тргни. „+" → пребарување низ типовите (алијаси) или залепен слободен список („млеко, 10 јајца…" → `parseList`).
- Голема бројка: најевтино на едно место (продавница); „−X ден. наспроти најскапата"; картичка „Со 2 продавници: Y ден." ако заштедата е > 0; ленти за сите 9 продавници; допир на продавница → ставките (производ, пакувања, цена, акција/клуб-цена) како во `npm run basket`.
- Ставка што ја нема во продавница: јасно означена („нема: сирење"), а нецелосната кошничка се рангира после целосните (како `compareBasket`).
- Списокот се чува во `localStorage`; празна кошничка → примерен список со едно допирање.

### Поевтинето
- Следени типови = типовите што биле во кошничката + рачно следени (ѕвезда во Пребарај); може да се тргнат.
- `dropsSince(следени, последна посета)`: картички по производ (тип, име, денес / прецртана стара цена, −%, каде) и „вистинска акција?" (`PROMO_VERDICT_TEXT`); најевтино по единица ако паднало.
- „Последна посета" = датумот на пакетот при претходното отворање (не часовникот на телефонот); првото отворање: последните 7 дена.
- Празно: „Ништо од следеното не поевтинело за 5% или повеќе од <датум>".

### Пребарај
- Поле со предлози од типовите (алијаси, кирилица и латиница „mleko"); резултат: најевтино во Велес за стандардната количина + листа по продавница (најевтиниот кандидат: производ, цена, акција); допир на производ → историја на цената (серија) и „вистинска акција?". Ѕвезда = следи го типот.
- Пребарување по име на производ надвор од типовите: не во v1 (бара сите ~40.000 имиња на телефонот).

### Продавници
- 9 продавници: синџир, број на производи, ажурирано (од ценовникот), ознака „застарено" ако маркетот не ажурирал > 2 дена (`isStale`); кратко за изворот (законска обврска од 18.04.2025).
- „Пријави погрешна цена": го нема во v1 — доаѓа со `price-reports`.

### Општо
- Мени долу: лебдечко стаклено, 4 копчиња ≥ 52 px, активното е полно; `aria-current`; работи со тастатура.
- Тема по телефонот (`prefers-color-scheme`); контраст на текст ≥ 4.5:1 и врз стаклените картички.
- Ширини 360–430 px како главни; на компјутер истата апликација центрирана (без посебен распоред).
- Офлајн: последниот пакет од кешот, со „цени од <датум>".
- Инсталирање: `manifest.webmanifest` + икони.

## Технологија

- Next.js 16 (App Router, static export), React, TypeScript; стил: обичен CSS со CSS променливи (како макетата), без Tailwind. Фонтови: `next/font/google` (Onest, Unbounded) — се хостираат со апликацијата.
- Нови зависности: `next`, `react`, `react-dom` (прво прашај за секоја друга).
- Сите постојни `npm` команди остануваат; нови: `npm run build-data`, `npm run dev` (Next), `npm run build` (build-data + next build).

## Команди

```
npm run build-data              # public/data/*.json од data/
npm run dev                     # локално на http://localhost:3000 (и телефон на иста Wi‑Fi мрежа)
npm run build                   # build-data + next build → out/
npm test                        # node:test (логиката) 
npm run typecheck
```

## Структура

```
app/                  Next.js: layout, страници по екран, CSS
app/components/       мени, меури, картички
src/                  постојната логика (без промена на однесувањето)
src/publish/          build-data: пакет за телефонот + тестови
public/data/          излезот на build-data (надвор од git)
.github/workflows/    daily.yml: fetch → build-data → deploy
```

## Критериуми за успех

1. `npm run build-data` на вистинските податоци прави `types.json` ≤ 2 MB необработено; тест: кошничката пресметана од пакетот е иста како `compareBasket` од целосните снимки за примерниот список (552 Жито Ване, 532 со две).
2. Тест: `dropsSince` и `promoCheck` од пакетот даваат исто како од целосната историја (на синтетички податоци).
3. Сите 4 екрани работат локално (`npm run dev`) на телефон 360 px и 430 px, во светла и темна тема, како макетата; навигација само со тастатура минува низ менито.
4. Кошничката, следените типови и последната посета остануваат по затворање и отворање.
5. Прво вчитување: JavaScript ≤ 200 KB компресирано (без пакетот со цени); пакетот со цени ≤ 400 KB компресирано.
6. GitHub Actions: рачно пуштање и закажано дневно — нови цени на Vercel; паднат маркет не ја спречува објавата (останува претходната снимка, „застарено" во Продавници); податоците преживуваат меѓу деновите.
7. `npm test`, `npm run typecheck`, `npm run build` поминуваат.

## Тестирање

- Логиката: `node:test` како досега; `src/publish/` со тестови (пакетот е подмножество што дава исти резултати).
- UI: рачно на телефон + проверка во прелистувач (ширини, тема, тастатура); без нова рамка за тестови во v1.
- Pipeline: рачно пуштање на workflow пред закажаното.

## Граници (додатно на `SPEC.md`)

- **Секогаш:** цените на телефонот се пресметуваат со истите функции како командите (нема втора логика); лични податоци само во прелистувачот.
- **Прво прашај:** нова зависност надвор од `next`/`react`; промена на бојата/распоредот надвор од макетата; јавен GitHub repo (е-поштата во историјата).
- **Никогаш:** аналитика, колачиња за следење или рекламни скрипти; токени (Vercel, GitHub) во кодот — само во GitHub Secrets.
